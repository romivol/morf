# why

Every AI tool speaks its own dialect.

A skill, an agent, a rule — each tool wants a different shape, a different folder, different frontmatter. Today you copy files around and hand-fix each one, then do it again for the next tool. morf is the translator: one command, converted for every tool you use.

# conversion

The same agent, reshaped for each tool.

morf rewrites the frontmatter, tool lists and paths into each tool's own format instead of copying the file as-is. Pick a target to see what morf produces:

sourcebug-finder.md
---
name: bug-finder
description: Finds bugs
tools: [Read, Grep, Bash]
model: sonnet
---
# Bug Finder
Reviews diffs for logic
errors and edge cases…
→

# projects

  
The same setup, on every machine.

  
A project pins what it uses in morf.json. morf.lock.json records the exact commit and a content hash of each item. Commit both, then run morf sync anywhere.

  
$ morf init
$ morf install github.com/acme/agents --agent bug-finder --target claude cursor
$ git add morf.json morf.lock.json
# on another machine, or in CI
$ morf sync

  
Hashes are computed the same way on Windows, macOS and Linux, so a lockfile written on one verifies on the others.








  
# commands

  
Simple commands, all the way down.

  

    
$ morf install <url>
clone & convert into every detected tool

    
$ morf install <repo> --agent <name> --target claude
install one agent into Claude

    
$ morf install <repo> --skill <name> --target cursor
install one skill into Cursor

    
$ morf list --all
see what's installed, in every tool

    
$ morf update --all
pull latest for everything you installed

    
$ morf config default <tool>
set your primary target once

    
$ morf init
start a project: creates morf.json

    
$ morf sync
install exactly what the lockfile pins

    
$ morf sync --check
change nothing; exit 1 if the project has drifted

    
$ morf sync --frozen --yes
for CI: never rewrites the lockfile

    
$ morf install <repo> --mcp <name> --hook <name>
install an MCP server and a hook set

    
$ morf install <repo> --dry-run
show the plan, write nothing

    
$ morf uninstall --agent <name>
remove an item from every tool it is in

# faq

  
Good to know.

  

    
Does morf change my original files?
No. morf reads your source repo and writes converted copies into each tool's directory. Your source is never modified. In config files you also edit, such as settings.json or .mcp.json, morf adds and removes only its own entries.

    
What happens for a tool that doesn't support a primitive?
morf marks it and skips only that piece — everything else still installs. For example, Codex has no project-level prompts, so in a project morf skips them, says so in the plan, and installs the rest normally.

    
Do I need a config file?
No. morf install <url> works with nothing set up. A project file (morf.json) is optional, for teams that want a pinned, shared setup.

    
Which git hosts work?
Any git server, public or private: GitHub, GitLab, self-hosted. Use an https or ssh address. Plain http:// and git:// addresses are not accepted.

    
Will it overwrite something I edited locally?
No. If morf detects local changes to an installed item, it skips it and tells you to re-run with --force if you really want to overwrite.

    
What happens when a repo updates?
Run morf update. It pulls the latest version of what you installed, skips anything you edited locally, and leaves the rest untouched. In a project it also rewrites the lockfile.

    
What is the lockfile for?
morf.json says what a project wants, for example the main branch of a repo. morf.lock.json records what that resolved to: the exact commit and a hash of each item. Two people who sync a week apart get the same files.

    
Is it safe to sync a project someone else set up?
morf shows the full plan before changing anything and asks first. Hooks and MCP servers are listed with the commands they run and need a second confirmation. In CI nothing installs without --yes, and hooks and MCP servers also need --allow-exec.

    
I'm on 1.x. What changes when I upgrade?
Your installed items are left as they are and nothing is rewritten, but a few defaults change; see Upgrading from 1.1.2 in the changelog.
